Небольшой апплет KDE Plasma 6 без зависимостей, который показывает баланс и
использование вашего API DeepSeek на панели, с подробным всплывающим окном.

- **Панель:** значок плюс выбранное вами число (баланс, расход за сегодня,
  токены за сегодня, расход за период или расход за всё время).
- **Всплывающее окно:** баланс, расход за сегодня/период/всё время, оценочное
  «осталось дней», входящие/исходящие/кэшированные токены и количество
  запросов, спарклайн дневных расходов и разбивка по каждому API-ключу.
- **Секреты хранятся в KWallet**, а не в файле конфигурации виджета.
- **Никаких зависимостей времени выполнения**, кроме Plasma и Qt: сетевой доступ —
  это QML `XMLHttpRequest`, разбор — на чистом JavaScript, а KWallet доступен
  через `kwallet-query`.

## Установка

```sh
./install.sh            # install or upgrade for the current user
./install.sh --pack     # write ai-usage.plasmoid for distribution
./install.sh --uninstall
```

Затем добавьте **DeepSeek Usage** на панель или на рабочий стол. Щёлкните виджет
правой кнопкой → _Настроить…_, чтобы добавить свои учётные данные.

## Учётные данные

Существуют два разных типа учётных данных, и они не взаимозаменяемы.

|                  | API-ключ                                 | Токен сессии                                                               |
| ---------------- | ---------------------------------------- | -------------------------------------------------------------------------- |
| Где получить     | <https://platform.deepseek.com/api_keys> | значение, которое сайт платформы сохраняет после входа в систему           |
| Область действия | доступ к API вашей учётной записи        | **полный доступ к учётной записи**, включая создание и удаление API-ключей |
| Что даёт         | только баланс                            | баланс, расход за всё время и историю использования                        |
| Где хранится     | `deepseek-api-key` в KWallet             | `deepseek-session-token` в KWallet                                         |

### Как получить токен сессии

1. Войдите на <https://platform.deepseek.com> в браузере.
2. Откройте инструменты разработчика (F12 или ⌥⌘I в macOS).
3. Откройте вкладку **Application** (**Storage** в Firefox) → **Local Storage** → `https://platform.deepseek.com`.
4. Найдите ключ с именем `userToken` и скопируйте **только токен внутри него**. Запись — это объект JSON — `{"value":"…","__version":"0"}` — а токен сессии это лишь строка после `value:`.

> [!TIP]
> Копирование всей записи — самая частая ошибка, и оно приводит к `Authorization Failed (invalid token)`: в запрос уходит `{"value":…}` там, где должен быть токен. Виджет всё равно её разворачивает, поэтому копия в кавычках или целый заголовок `Bearer …` тоже подойдут.

Оба записываются в KWallet (кошелёк `kdewallet`, папка `Plasma`) и читаются
обратно с помощью `kwallet-query`. Одного API-ключа достаточно для баланса;
добавление токена сессии включает разделы использования. Если токен сессии
перестаёт работать, виджет возвращается к отображению баланса и сообщает причину.

> [!WARNING]
> Токен сессии так же могуществен, как ваш пароль. Обращайтесь с ним
> соответствующе и удалите его из KWallet, если перестанете использовать
> расширенный режим.

## Источники данных

Виджет является гибридным, потому что DeepSeek предоставляет два несвязанных API.

**Официальный API** (`api.deepseek.com`) — аутентификация по API-ключу,
документирован, надёжен, но сообщает только баланс:

```
GET https://api.deepseek.com/user/balance
Authorization: Bearer <API_KEY>
```

**Platform API** (`platform.deepseek.com/api/v0`) — бэкенд, стоящий за
веб-страницей использования. Он аутентифицируется по сессии и **недокументирован**,
поэтому может измениться в любой момент:

```
GET /users/get_user_summary
GET /usage/by_api_key/amount?start=&end=&tz=
GET /usage/by_api_key/cost?start=&end=&tz=
authorization: Bearer <SESSION_TOKEN>
```

Две особенности, о которых стоит знать:

- Platform API отвечает **HTTP 200 даже при ошибках аутентификации**, помещая
  реальный статус в тело JSON (`{"code":40003,...}`). Поэтому виджет
  классифицирует результаты по телу ответа, а никогда по HTTP-статусу.
- Полезные нагрузки стоимости и токенов вкладывают свои ряды по-разному
  (`data.biz_data.data[] .series[]` для стоимости, `data.biz_data.series[]` для
  токенов).

Поскольку документированной конечной точки "usage" не существует, показатели
расходов и значение «осталось дней» **выводятся** из этого API и помечаются как
таковые во всплывающем окне.

## Конфигурация

| Параметр               | По умолчанию | Значение                                |
| ---------------------- | ------------ | --------------------------------------- |
| Интервал обновления    | 300 с        | как часто опрашивать (минимум 30 с)     |
| На панели отображается | Баланс       | какое число появляется на панели        |
| Период расходов        | 30 дней      | окно для итогов за период и спарклайна  |
| Скрывать все суммы     | выкл.        | заменять каждую сумму на экране точками |

Разбивка по ключам перечисляет только **имена** API-ключей. Маскированный
идентификатор ключа, который сообщает платформа, намеренно нигде не отображается.

## Пиковое и непиковое ценообразование

DeepSeek берёт половину цены вне пиковых часов, поэтому виджет показывает, какой
тариф действует: маленькая точка на чипе панели, а также состояние и оставшееся
в нём время во всплывающем окне и всплывающей подсказке.

- **зелёный** — непиковое время: вы платите по сниженному тарифу
- **красный** — пиковое время: вы платите полную цену
- **нейтральный** — неизвестно: см. ниже

Расписание [документировано](https://api-docs.deepseek.com/quick_start/pricing)
как _01:00–04:00 и 06:00–10:00 UTC, с понедельника по пятницу, за исключением
официальных праздников Китая_; все остальные часы — непиковые, включая выходные
и праздники целиком.

### Почему может отображаться «Неизвестно»

Часть правила, касающаяся дня недели и времени суток, точна и применяется всегда.
Исключение для праздников — другое: Госсовет публикует даты следующего года только
в ноябре или декабре и может их пересматривать, поэтому это данные, которые
приходится поддерживать вручную, и их нельзя вывести.

Поэтому виджет не будет угадывать. `CHINESE_HOLIDAYS` в
`contents/ui/js/peak.js` содержит опубликованное расписание, блок за блоком, для
объявленных лет:

```js
addRange("2026-10-01", "2026-10-07"); // National Day
```

Когда запрашивается год, который таблица не охватывает, состояние сообщается как
**Неизвестно**, а не предполагается, что эти дни — обычные рабочие дни: такое
предположение показало бы пиковый тариф, тогда как DeepSeek взимал бы непиковую
цену. Оценочные даты также нельзя добавлять — по той же причине, но в обратную
сторону: неверная запись заявила бы о скидке, которой не существует.

### Поддержание в актуальном состоянии

`node --test tests/peak.test.mjs` включает намеренную сигнализацию о необходимости
обслуживания: он **падает, когда таблица перестаёт охватывать текущий год**, а
также падает, если какой-либо охваченный год выглядит заполненным наполовину.
Добавьте только что опубликованный год с помощью `addRange()`, и тесты снова
станут зелёными. Объявляется в ноябре/декабре на следующий год, так что это
ежегодная рутина.

## Разработка

Логика разбора, форматирования и команд KWallet живёт в модулях на чистом
JavaScript в `contents/ui/js/`, поэтому её можно тестировать без сеанса Plasma:

```sh
node --test tests/api.test.mjs tests/format.test.mjs tests/wallet.test.mjs
```

`tests/mock-platform-server.mjs` отдаёт записанные формы полезной нагрузки
Platform API — это единственный способ задействовать расширенный режим без
реальных учётных данных. Во время тестирования направьте `PLATFORM_BASE` в
`contents/ui/js/api.js` на `http://127.0.0.1:8731/api/v0`, затем верните как было.

Статические проверки для стороны QML:

```sh
qmllint contents/ui/*.qml contents/config/config.qml
```

Отрисовка апплета по одному разу на локаль, чтобы заметить кракозябры или текст,
выходящий за пределы всплывающего окна (текст на хинди и русском намного длиннее
английского):

```sh
tests/capture-locales.sh /tmp/shots zh_CN ru_RU hi_IN
```

### Непрерывная интеграция

Проверки выше выполняются в CI (`.github/workflows/ci.yml`), на стандартном
раннере Ubuntu и без Plasma: `node --test`, `./translate/build.sh --check`,
проверка синтаксиса QML с помощью `qmllint` и `./install.sh --pack`, чтобы
доказать, что архив для распространения всё ещё собирается. `qmllint` в Qt 6 не
разрешает никаких импортов, поэтому ему не нужны пакеты KDE, — именно это и делает
такую задачу вообще возможной.

Один рабочий процесс не запускается при push.
`.github/workflows/holiday-alarm.yml` запускает `tests/peak.test.mjs` первого числа
каждого месяца, потому что тот файл содержит намеренную сигнализацию: он падает,
когда таблица китайских праздников перестаёт охватывать текущий год, а Госсовет
публикует даты следующего года только в ноябре или декабре. Красный прогон там —
это напоминание добавить опубликованные блоки с помощью `addRange()`, а не ошибка.

## Переводы

Виджет поставляется с 17 каталогами: упрощённый китайский, английский (Индия),
хинди, индонезийский, французский, русский (Россия и Беларусь), испанский
(Испания и четыре латиноамериканских варианта), а также псевдонимы на «чистых»
языках, которые расширяют резервный выбор локали Qt. Переводы находятся в
`translate/`; см. [`translate/README.md`](translate/README.md) о рабочем процессе и
формате таблицы.

Этот README тоже переведён; языковые ссылки в начале страницы указывают на эти
файлы. Они представляют собой **машинные переводы этого документа, по одному
файлу на язык** — региональные варианты каталогов (`en_IN`, `ru_BY`, `es_419` и
четыре латиноамериканских кода испанского) используют README своего языка, а не
повторяют его.

```sh
./translate/merge.sh          # re-extract template.pot after changing i18n() calls
./translate/build.sh          # regenerate .po and compile .mo
./translate/build.sh --check  # CI: fail if any catalogue is out of date
```

> [!WARNING]
> **Каждый каталог машинно-сгенерирован и никогда не проверялся носителем
> языка.** Каждый `.po` фиксирует это в своём заголовке, а его поле
> `Language-Team` по-прежнему содержит заполнитель gettext "no catalogue has been
> claimed". Относитесь к ним как к отправной точке, а не как к завершённому
> переводу.
>
> **Приоритет для проверки: хинди, русский и упрощённый китайский** — языки, на
> которых этот виджет, скорее всего, будут использовать чаще всего, и те, где
> непроверенный перевод наименее приемлем. Всё остальное — бонус.

Выбранный путь для исправления этого — **собственные команды переводчиков KDE**
(решение D13): это единственный путь, который даёт _проверенные_ переводы от людей,
которые действительно говорят на языке. `Messages.sh` в корне репозитория уже
является точкой входа, которую ожидает инструментарий KDE, а
`translate/README.md` перечисляет конкретные шаги — главное предварительное
условие состоит в том, что виджет должен находиться в репозитории KDE, прежде чем
команды смогут его взять. Конфигурации Crowdin/Transifex оставлены только как
запасной вариант и явно помечены как никогда не запускавшиеся.

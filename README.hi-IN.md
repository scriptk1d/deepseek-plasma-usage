एक छोटा, निर्भरता-रहित KDE Plasma 6 एप्लेट जो पैनल में आपका DeepSeek API
बैलेंस और उपयोग दिखाता है, साथ में एक विस्तृत पॉपअप।

- **पैनल:** एक आइकन और आपके चुने हुए आंकड़े (बैलेंस, आज का खर्च,
  आज के टोकन, अवधि का खर्च या अब तक का कुल खर्च)।
- **पॉपअप:** बैलेंस, आज/अवधि/अब तक का खर्च, एक अनुमानित "शेष दिन",
  इनपुट/आउटपुट/कैश्ड टोकन और अनुरोधों की संख्या, दैनिक खर्च की
  स्पार्कलाइन और हर API कुंजी के अनुसार विवरण।
- **राज़ KWallet में रहते हैं**, कभी भी विजेट की कॉन्फ़िगरेशन फ़ाइल में नहीं।
- **Plasma और Qt के अलावा कोई रनटाइम निर्भरता नहीं**: नेटवर्क एक्सेस QML
  `XMLHttpRequest` है, पार्सिंग सादा JavaScript है, और KWallet तक
  `kwallet-query` के ज़रिये पहुँचा जाता है।

पैनल चिप के रूप में — आइकन, आपके चुने हुए आंकड़े, और पीक/ऑफ-पीक बिंदु:

## इंस्टॉल

```sh
./install.sh            # install or upgrade for the current user
./install.sh --pack     # write ai-usage.plasmoid for distribution
./install.sh --uninstall
```

इसके बाद **DeepSeek Usage** को किसी पैनल या डेस्कटॉप पर जोड़ें। अपनी
क्रेडेंशियल जोड़ने के लिए विजेट पर राइट-क्लिक करें → _कॉन्फ़िगर करें…_।

## क्रेडेंशियल

दो अलग-अलग क्रेडेंशियल होते हैं, और वे एक-दूसरे की जगह इस्तेमाल नहीं किए जा सकते।

|                     | API कुंजी                                | सेशन टोकन                                                              |
| ------------------- | ---------------------------------------- | ---------------------------------------------------------------------- |
| इसे कहाँ से लें     | <https://platform.deepseek.com/api_keys> | वह मान जो लॉग इन करने के बाद प्लेटफ़ॉर्म साइट सहेजती है                |
| दायरा               | आपके खाते की API पहुँच                   | **पूरे खाते तक पहुँच**, जिसमें API कुंजियाँ बनाना और हटाना भी शामिल है |
| आपको क्या देता है   | केवल बैलेंस                              | बैलेंस, अब तक का कुल खर्च और उपयोग इतिहास                              |
| इस रूप में संग्रहीत | KWallet में `deepseek-api-key`           | KWallet में `deepseek-session-token`                                   |

### सेशन टोकन कैसे प्राप्त करें

1. अपने ब्राउज़र में <https://platform.deepseek.com> पर लॉग इन करें।
2. डेवलपर टूल खोलें (F12, या macOS पर ⌥⌘I)।
3. **Application** टैब खोलें (Firefox में **Storage**) → **Local Storage** → `https://platform.deepseek.com`।
4. `userToken` नाम की कुंजी खोजें और **उसके अंदर का टोकन ही कॉपी करें**। वह प्रविष्टि एक JSON ऑब्जेक्ट है — `{"value":"…","__version":"0"}` — और सेशन टोकन केवल `value:` के बाद वाली स्ट्रिंग है।

> [!TIP]
> पूरी प्रविष्टि कॉपी करना ही सबसे आम गलती है, और यह `Authorization Failed (invalid token)` के साथ विफल होती है, क्योंकि अनुरोध में टोकन की जगह `{"value":…}` चला जाता है। विजेट इसे हर हाल में खोल देता है, इसलिए कोट्स वाली कॉपी या पूरा `Bearer …` हेडर भी काम करता है।

दोनों KWallet में लिखे जाते हैं (वॉलेट `kdewallet`, फ़ोल्डर `Plasma`) और
`kwallet-query` से वापस पढ़े जाते हैं। अकेले API कुंजी बैलेंस के लिए पर्याप्त है;
सेशन टोकन जोड़ने से उपयोग वाले हिस्से सक्षम हो जाते हैं। यदि सेशन टोकन काम
करना बंद कर दे, तो विजेट बैलेंस पर वापस चला जाता है और आपको कारण बताता है।

> [!WARNING]
> सेशन टोकन आपके पासवर्ड जितना ही शक्तिशाली है। इसे पासवर्ड की तरह ही संभालें,
> और यदि आप रिच मोड का उपयोग बंद कर दें तो इसे KWallet से हटा दें।

## डेटा स्रोत

विजेट एक हाइब्रिड है क्योंकि DeepSeek दो असंबंधित API उपलब्ध कराता है।

**आधिकारिक API** (`api.deepseek.com`) — API कुंजी से प्रमाणित, प्रलेखित,
विश्वसनीय, लेकिन यह केवल बैलेंस बताता है:

```
GET https://api.deepseek.com/user/balance
Authorization: Bearer <API_KEY>
```

**प्लेटफ़ॉर्म API** (`platform.deepseek.com/api/v0`) — वेब उपयोग पृष्ठ के पीछे
का बैकएंड। यह सेशन से प्रमाणित होता है और **अप्रलेखित** है, इसलिए यह कभी भी
बदल सकता है:

```
GET /users/get_user_summary
GET /usage/by_api_key/amount?start=&end=&tz=
GET /usage/by_api_key/cost?start=&end=&tz=
authorization: Bearer <SESSION_TOKEN>
```

जानने योग्य दो विचित्रताएँ:

- प्लेटफ़ॉर्म API **प्रमाणीकरण विफल होने पर भी HTTP 200** लौटाता है, और असली
  स्थिति JSON बॉडी (`{"code":40003,...}`) में डालता है। इसलिए विजेट परिणामों
  को पेलोड से वर्गीकृत करता है, कभी भी HTTP स्थिति से नहीं।
- लागत और टोकन पेलोड अपनी सीरीज़ को अलग-अलग तरीके से नेस्ट करते हैं (लागत के
  लिए `data.biz_data.data[]
.series[]`, टोकन के लिए `data.biz_data.series[]`)।

चूँकि कोई प्रलेखित "उपयोग" एंडपॉइंट नहीं है, खर्च के आंकड़े और
"अनुमानित शेष दिन" का मान इस API से **व्युत्पन्न** किए जाते हैं और पॉपअप में
उन्हें इसी रूप में चिह्नित किया जाता है।

जो मास्क किया हुआ कुंजी id बताता है, वह जानबूझकर कहीं भी प्रदर्शित नहीं किया
जाता।

## पीक और ऑफ-पीक मूल्य निर्धारण

DeepSeek अपने पीक घंटों के बाहर आधी कीमत लेता है, इसलिए विजेट दिखाता है कि
कौन-सी दर लागू है: पैनल चिप पर एक छोटा बिंदु, और पॉपअप तथा टूलटिप में स्थिति
और उसमें बचा समय।

- **हरा** — ऑफ-पीक: आप रियायती दर चुका रहे हैं
- **लाल** — पीक: आप पूरी कीमत चुका रहे हैं
- **तटस्थ** — अज्ञात: नीचे देखें

यह समय-सारणी [प्रलेखित](https://api-docs.deepseek.com/quick_start/pricing) है:
_01:00–04:00 और 06:00–10:00 UTC, सोमवार से शुक्रवार, चीनी सार्वजनिक छुट्टियों
को छोड़कर_; बाकी सभी घंटे ऑफ-पीक हैं, जिसमें सप्ताहांत और छुट्टियाँ पूरी तरह
शामिल हैं।

### यह "अज्ञात" क्यों कह सकता है

उस नियम का सप्ताह-दिवस और दिन-का-समय वाला हिस्सा सटीक है और हमेशा लागू होता
है। छुट्टी का अपवाद अलग है: राज्य परिषद (State Council) अगले वर्ष की तारीखें
केवल नवंबर या दिसंबर में प्रकाशित करती है और उन्हें संशोधित भी कर सकती है,
इसलिए यह ऐसा डेटा है जिसे हाथ से बनाए रखना पड़ता है और जिसे व्युत्पन्न नहीं
किया जा सकता।

इसलिए विजेट अनुमान नहीं लगाएगा। `contents/ui/js/peak.js` में `CHINESE_HOLIDAYS`
उन वर्षों के लिए प्रकाशित समय-सारणी को खंड-दर-खंड रखता है जिनकी घोषणा हो चुकी है:

```js
addRange("2026-10-01", "2026-10-07"); // National Day
```

जब ऐसे वर्ष के बारे में पूछा जाता है जिसे तालिका कवर नहीं करती, तो उन दिनों को
साधारण कार्यदिवस मानने के बजाय स्थिति **अज्ञात** बताई जाती है — ऐसा मानने पर
पीक बताया जाएगा जबकि DeepSeek ऑफ-पीक दर ले रहा था। अनुमानित तारीखें भी नहीं
जोड़ी जानी चाहिए, उसी कारण से उलटी दिशा में: गलत प्रविष्टि ऐसी छूट का दावा
करेगी जो मौजूद ही नहीं है।

### इसे अद्यतन रखना

`node --test tests/peak.test.mjs` में एक जानबूझकर रखा गया रखरखाव अलार्म है: यह
**तब विफल हो जाता है जब तालिका वर्तमान वर्ष को कवर नहीं करती**, और यदि कोई
कवर किया गया वर्ष आधा-भरा दिखे तो भी विफल हो जाता है। नए प्रकाशित वर्ष को
`addRange()` से जोड़ें और परीक्षण फिर से पास हो जाते हैं। अगले वर्ष के लिए
नवंबर/दिसंबर में घोषणा होती है, इसलिए यह साल में एक बार का काम है।

## विकास

पार्सिंग, फ़ॉर्मेटिंग और KWallet कमांड का तर्क `contents/ui/js/` के अंतर्गत
सादे JavaScript मॉड्यूल में रहता है ताकि उन्हें Plasma सत्र के बिना परीक्षण
किया जा सके:

```sh
node --test tests/api.test.mjs tests/format.test.mjs tests/wallet.test.mjs
```

`tests/mock-platform-server.mjs` प्लेटफ़ॉर्म API के रिकॉर्ड किए गए पेलोड आकार
परोसता है, जो लाइव क्रेडेंशियल के बिना रिच मोड आज़माने का एकमात्र तरीका है।
परीक्षण के दौरान `contents/ui/js/api.js` में `PLATFORM_BASE` को
`http://127.0.0.1:8731/api/v0` पर इंगित करें, फिर उसे वापस बदल दें।

QML पक्ष के लिए स्थैतिक जाँच:

```sh
qmllint contents/ui/*.qml contents/config/config.qml
```

प्रत्येक लोकेल के लिए एप्लेट को एक बार रेंडर करना, ताकि मोजीबेक या पॉपअप से
बाहर निकलने वाला टेक्स्ट पकड़ा जा सके (हिन्दी और रूसी अंग्रेज़ी से कहीं अधिक
लंबे होते हैं):

```sh
tests/capture-locales.sh /tmp/shots zh_CN ru_RU hi_IN
```

### निरंतर एकीकरण

ऊपर की जाँचें CI (`.github/workflows/ci.yml`) में चलती हैं, एक सामान्य Ubuntu
रनर पर और Plasma के बिना: `node --test`, `./translate/build.sh --check`,
`qmllint` के साथ एक QML सिंटैक्स जाँच, और `./install.sh --pack` यह साबित करने
के लिए कि वितरण अभिलेख अभी भी बनता है। Qt 6 पर `qmllint` कोई इम्पोर्ट हल नहीं
करता, इसलिए उसे किसी KDE पैकेज की ज़रूरत नहीं होती, और यही बात उस जॉब को
संभव बनाती है।

एक वर्कफ़्लो push पर नहीं चलता। `.github/workflows/holiday-alarm.yml` हर महीने
की पहली तारीख को `tests/peak.test.mjs` चलाता है, क्योंकि उस फ़ाइल में एक
जानबूझकर रखा गया अलार्म है: यह तब विफल हो जाता है जब चीनी-छुट्टी की तालिका
वर्तमान वर्ष को कवर करना बंद कर देती है, और राज्य परिषद अगले वर्ष की तारीखें
केवल नवंबर या दिसंबर में प्रकाशित करती है। वहाँ लाल चलन यह याद दिलाता है कि
प्रकाशित खंडों को `addRange()` से जोड़ें, यह कोई बग नहीं है।

## अनुवाद

विजेट 17 कैटलॉग के साथ आता है: सरलीकृत चीनी, अंग्रेज़ी (भारत), हिन्दी,
इंडोनेशियाई, फ़्रेंच, रूसी (रूस और बेलारूस), स्पेनिश (स्पेन और चार
लैटिन-अमेरिकी रूप), साथ ही केवल-भाषा उपनाम जो Qt के लोकेल फ़ॉलबैक को चौड़ा
करते हैं। अनुवाद `translate/` में रहते हैं; कार्यप्रवाह और तालिका प्रारूप के
लिए [`translate/README.md`](translate/README.md) देखें।

यह README भी अनूदित है; पृष्ठ के शीर्ष पर दिए भाषा-लिंक उन्हीं फ़ाइलों की ओर
इशारा करते हैं। वे **इस दस्तावेज़ के मशीन अनुवाद हैं, प्रति भाषा एक फ़ाइल तक
सीमित** — क्षेत्रीय कैटलॉग रूप (`en_IN`, `ru_BY`, `es_419` और चार
लैटिन-अमेरिकी स्पेनिश कोड) अपनी भाषा के README को दोहराने के बजाय साझा करते हैं।

```sh
./translate/merge.sh          # re-extract template.pot after changing i18n() calls
./translate/build.sh          # regenerate .po and compile .mo
./translate/build.sh --check  # CI: fail if any catalogue is out of date
```
